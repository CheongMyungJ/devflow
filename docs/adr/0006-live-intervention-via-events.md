# ADR-0006: 세션 관찰·개입 허용, 개입은 이벤트로 기록

- 상태: Accepted
- Superseded by [ADR-0022](0022-role-hitl-and-independent-questions.md) — 독립 읽기 전용 질문 CLI의 메시지 선기록 범위만. 관리형 역할 세션은 유지.
- 날짜: 2026-09-18

## 상황
초기 제안은 "Worker 와 실시간 대화 불가" 였다. 그러나 사람은 세션이 돌아가는 흐름을 보고 싶을 수 있고, 거기서 방향을 잡아 주는 편이 끝난 뒤 재작업시키는 것보다 싸다. 지켜야 할 원칙은 "세션이 사라져도 복원 가능" 이지 "사람이 세션에 들어가지 않는다" 가 아니다.

## 결정
- 관찰은 제약 없이 허용한다 (`runner.stream`, transcript 저장).
- 개입을 허용한다. 단, 메시지는 `commands.send_message(run_id, text)` 를 거쳐 **live Feedback 이벤트로 기록된 뒤** 세션에 전달된다. 재실행 시 Context 패킷에 포함된다.
- Worker 는 Step 종료 시 "실행 중 받은 지시 요약" 을 출력한다. 사람은 검토 시 그중 Task 요구사항으로 올릴 것을 확인한다.
- 세션 안의 동의는 승인이 아니다 (ADR-0004).
- Reviewer 세션에는 개입하지 않는다. Planner 는 Step 제안 확인 단계에서 수정한다.

## 이유
기록 없이 세션에만 들어간 지시는 세션과 함께 사라지고, Reviewer/Planner 가 모르는 요구사항이 된다. 개입 기록은 Step 크기와 Step 정의 품질을 개선하는 데이터다. 개입이 잦으면 Step 이 너무 크거나 정의가 부실하다는 신호다.

## 포기한 대안
- 개입 금지: 원칙은 지키지만 실사용에서 비효율적이다.
- 세션에 직접 입력(기록 없음): 복원성이 깨진다.
